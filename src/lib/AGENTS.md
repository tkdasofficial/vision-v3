- Chat AI is split into `src/lib/ai/`: `modes.ts` (the four user modes + legacy id migration), `task-router.ts` (pure per-request classifier, tested), `models.server.ts` (inventory + per-mode candidates, max 3), `providers.server.ts` (endpoints/keys/timeouts), `prompts.server.ts`; `/api/chat` only orchestrates and reports the workflow via X-Vision-Execution/X-Vision-Output headers. Why: each part can fail or change independently and the router never alters the selected mode.
- User preferences live as validated JSON in D1 `user_settings.prefs` (`src/lib/settings.ts`); /api/chat reads them server-side, and Research web search runs in `src/lib/search/search.server.ts` (parallel providers, normalized + de-duplicated). Why: request bodies can't spoof preferences and each search source can fail alone.
- Research reports are stored in D1 `research_documents` (owner-only, server functions in `documents.functions.ts`, not in the generic query layer) and shown as a card linking to /documents/$docId; code output uses `components/chat/code-block` + `full-screen-code-view`. Why: documents stay permission-checked on the server and renderers stay reusable.
